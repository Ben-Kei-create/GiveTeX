# ボードゲーム AI のソース集（GiveTex）

CPU と対戦できるボードゲーム9種の、プログラム一式です。
`index.html` をブラウザで開くと、そのまま遊べます（インターネットは、文字のフォントを読むときだけ使います）。

> うまく動かないときは、フォルダの中で `python3 -m http.server` を実行して、ブラウザで `http://localhost:8000/` を開いてください。

## 入っているもの

| ファイル | ゲーム | CPU の考え方 |
|---|---|---|
| `reversi.js` | リバーシ | マスごとの点数表（`W`）＋ 先読み（`search`） |
| `gomoku.js` | 五目ならべ | 「ここに置いたら何個ならぶか」を点数にする（`score`） |
| `connect4.js` | 四目ならべ | 先読み（`ab`） |
| `checkers.js` | チェッカー | 先読み（`mm`） |
| `mancala.js` | マンカラ | 先読み（`mm`） |
| `chess.js` | チェス | 駒の点数（`V`）＋ 場所の点数表（`PST`）＋ 先読み（`search`） |
| `shogi.js` | 将棋 | 駒の点数（`VAL`・持ち駒は `PVAL`）＋ 先読み（`search`） |
| `go.js` | 囲碁（9路） | 先読みはしない。「取れる」「取られそう」などを点数にして一番いい手を選ぶ（`ai`） |
| `mahjong.js` | 麻雀（2人打ち） | あがりまであと何枚か（シャンテン数：`shanten`）がいちばん減る牌を捨てる |
| `board.js` | 入れもの | ゲームをえらぶ画面。選ばれたゲームのファイルだけ読みこむ |

## CPU はどうやって手を決めているの？

大きく分けて、2つの部品があります。

1. **評価（ひょうか）**：いまの盤面が「自分にとって何点か」を数字にする。
   - リバーシなら、角は +100 点、角のとなりは −50 点、のように場所で点をつけます（`reversi.js` の `W`）。
   - チェスや将棋なら、駒の種類ごとの点数を足します（`V`、`VAL`）。
2. **先読み（さきよみ）**：「自分がこう打つ → 相手はいちばん困る手を返す → 自分は…」と、何手か先まで全部ためして、いちばん点が高くなる手を選ぶ。
   - これを **ミニマックス法** といいます。関数の引数に `d`（あと何手読むか）があるのが目印です。
   - 引数の `a` と `be` は **アルファ・ベータ法** のしるしです。「どうせ選ばれない手」を途中で読むのをやめて、速くします。

「CPU：よわい／ふつう／つよい」は、おもに **何手先まで読むか** を変えています。

## やってみよう（かんたん → むずかしい）

1. `reversi.js` の点数表 `W` の角（100）を 0 にすると、CPU の打ち方はどう変わる？
2. `chess.js` の `V` で、ナイト（`n`）の点数をクイーン（`q`）より高くしてみよう。CPU は何を大事にするようになる？
3. `gomoku.js` の `score` で、「3つならび」の点を上げると、守りと攻めのどちらが強くなる？
4. `connect4.js` で、読む深さを1つ増やすと、考える時間はどのくらい長くなる？（列は7つ。1手深くなると、だいたい何倍？）
5. `go.js` の `ai` は先読みをしていません。なぜ囲碁では「全部ためす」のがむずかしいのか、置ける場所の数から考えてみよう。
6. 自分のゲーム（たとえば三目ならべ）を、同じ形で1ファイル作って `board.js` の `GAMES` に足してみよう。

## しくみのメモ

- どのゲームも `window.BG.<名前>` に「ゲームを始める関数」を入れています。`board.js` がそれを呼び出します。
- 将棋とチェスは、ルールどおりの手だけを作れているかを「perft（パーフト）」という方法で確かめてあります（最初の局面から、1手・2手・3手で何通りあるかを数えて、知られている数とくらべる）。
  - 将棋：30 → 900 → 25470 → 719731 ／ チェス：20 → 400 → 8902
