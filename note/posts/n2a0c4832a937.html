!T61 個人開発アプリApp申請作業工程まとめ

2026.05.11

個人開発で作っていたiOSアプリを、App Store申請できる状態まで
整理。

このアプリは、ビールに関する雑学を4択クイズ形式で学べるアプリです。
注ぎ方、スタイル、醸造方法などの知識を、初級・中級・上級の3段階でテンポよく学べる構成にしています。

今回は、実際にApp Store申請へ向けて行った作業工程をまとめます。

個人開発でアプリを作ると、コードを書くところまでは楽しいのですが、申請前になると急にやることが増えます。

アイコン、問題データ、署名設定、AdMob、プライバシーポリシー、Support URL、実機確認、Archiveなど、
地味だけど避けられない作業が一気に出てきます。

今回はClaudeにも手伝ってもらいながら、
上から順にチェックしていきました。

アプリ概要

今回申請準備を進めたアプリは、以下のような内容です。

アプリ名：BeerQuiz

主な機能は以下です。

  • 4択クイズ

  • 初級・中級・上級の難易度選択

  • 問題ごとの制限時間

  • スコア結果表示

  • Google AdMobバナー広告

  • プライバシーポリシーへのリンク

技術構成は Swift / SwiftUI です。

構成としては、主に以下のようになっています。

まずは不要ファイルの整理

最初に確認したのは、Gitの状態とAppIcon関連のファイルです。

その中で、古い app_icon.png がまだ残っていることが分かりました。

App Store申請前の状態では、アイコンまわりに不要なファイルが残っていると、警告や混乱の原因になります。

そこで、不要な app_icon.png を削除し、GitHubへプッシュしました。

これで、アイコン関連の警告は解消されました。

App Store申請前のチェックリストを整理

次に、申請前に必要な項目を整理しました。

Claude側で確認・対応できるものと、自分がXcodeやApp Store Connect上で作業する必要があるものを分けました。

まず、すでに完了していた項目です。

項目状態問題数125問完了アイコン全サイズ完了アプリ表示名 BeerQuiz完了プライバシーポリシーURL設定済み

一方で、App Store申請に向けて自分で確認・作業する必要があるものは以下でした。

項目優先度Apple Developer Team IDをXcodeに設定必須AdMob本番アプリID / 広告ユニットIDの確認必須Xcode 26以降でビルド確認必須実機またはTestFlightで動作確認必須App Store ConnectでApp作成必須スクリーンショット作成必須App Privacyの回答必須年齢制限、アルコール関連コンテンツの扱い重要

この時点で、「アプリの中身はほぼできているけど、申請作業はまだまだある」という状態でした。

Apple Developer Team IDを設定

まず最初に対応したのが、Apple Developer Team IDの設定です。

project.yml を確認すると、以下のように DEVELOPMENT_TEAM が空欄になっていました。

DEVELOPMENT_TEAM: ""

このままだと、Xcodeで署名まわりが正しく設定されません。

Apple DeveloperのTeam IDを確認し、以下の値を設定しました。

設定後は、project.yml に反映してGitHubへプッシュしました。

これで、Xcode側でSigning & Capabilitiesを開いたときに、自分のDeveloper Teamが使える状態になりました。

Xcode側では以下を確認します。

  • git pull で最新状態にする

  • app.xcodeproj を開く

  • Target → Signing & Capabilities を確認

  • Teamが正しく設定されているか確認

  • Automatically manage signing がオンになっているか確認

このステップで、App Store申請に必要な署名設定の土台が整いました。

AdMob IDを確認

次にAdMobのIDを確認しました。

広告を使うアプリの場合、申請前に特に注意したいのが、Debug用のテスト広告IDとRelease用の本番広告IDの切り分けです。

確認した結果は以下でした。

DebugではGoogle公式のテスト広告ID、Releaseでは本番広告ユニットIDを使う形になっていました。

これは望ましい状態です。

個人開発だと、テスト広告IDのままリリースしてしまったり、逆に開発中に本番広告を表示してしまったりするリスクがあります。

今回はその点を事前に確認できたので安心でした。

Xcode 26.4.1でArchive確認

次に、Xcodeのバージョンを確認しました。

使用していたXcodeは以下でした。

Version 26.4.1

要件としてXcode 26以降が必要だったため、この点は問題ありませんでした。

その後、Xcodeで Product → Archive を実行しました。

結果、Archiveは成功しました。

これはかなり大きなチェックポイントです。

App Store申請前は、Simulatorで動くだけでは不十分で、Archiveが通るかどうかを必ず確認する必要があります。

今回、Archiveが成功したことで、少なくともビルド・署名・構成面では申請に近い状態まで来ていることが確認できました。

GitHub PagesのURL確認

次に確認したのが、プライバシーポリシーとサポートページのURLです。

App Store Connectでは、GitHubリポジトリのURLではなく、公開されているWebページのURLが必要になります。

ここで少し気になったのが、「GitHubリポジトリのURLも必要なのか？」という点です。

結論として、
GitHubリポジトリのURLはApp Store Connectへの入力には不要 です。

必要なのは、ユーザーがアクセスできるプライバシーポリシーURLとサポートURLです。

GitHub Pagesが有効になっているか確認するため、実際にブラウザでプライバシーポリシーURLを開きました。

結果、ページは正常に表示されました。

つまり、GitHub Pages側も問題なしです。

プライバシーポリシーをGitHub上で修正した場合、再Archiveは必要か？

途中で、プライバシーポリシーの index.html をGitHub上で修正しました。

ここで気になったのが、

「HTMLを修正したら、もう一度XcodeでArchiveし直す必要があるのか？」

という点です。

結論は、再Archive不要 です。

理由はシンプルで、

プライバシーポリシーHTMLはアプリ内に同梱されているファイルではなく、アプリから外部URLとしてブラウザで開くページだからです。

つまり、GitHub Pages上のHTMLを修正すれば、アプリ側を再ビルドしなくても最新版が表示されます。

アプリ内のコードやリソースを変更した場合は再Archiveが必要ですが、外部Webページだけを更新した場合は不要です。

ここは、個人開発者が少し迷いやすいポイントだと思います。

実機確認

Archiveが通った後は、実機確認です。

XcodeからiPhoneへ直接インストールし、以下の項目を確認しました。

確認項目内容ホーム画面表示が崩れていないかスタートボタンクイズ開始できるかクイズ画面問題と選択肢が表示されるか回答処理正解・不正解が表示されるか難易度初級・中級・上級が動くかAdMobバナー下部に広告枠が表示されるかプライバシーポリシーリンクブラウザでページが開くか結果画面スコア結果が表示されるか

実機確認の結果、問題なく動作しました。

これで、申請前のアプリ本体確認は一通り完了です。

今回やってよかったこと

今回の申請準備で、特にやってよかったと感じたのは以下です。

1. Claudeにチェックリスト化してもらったこと

App Store申請前は、やることが散らばりがちです。

  • Xcodeでやること

  • GitHubでやること

  • App Store Connectでやること

  • AdMobで確認すること

  • Webページとして公開すること

これらを頭の中だけで管理すると、かなり混乱します。

今回はClaudeに、

「Claude側でできること」
「自分しかできないこと」
「優先度が高いこと」

に分けてもらったことで、かなり進めやすくなりました。

2. AdMobのDebug / Releaseを確認したこと

広告IDまわりは、ミスると怖い部分です。

Debugではテスト広告、Releaseでは本番広告という切り分けができているか確認できたのは大きかったです。

3. GitHub PagesのURLを事前確認したこと

App Store ConnectにURLを入力してから404に気づくと面倒です。

今回は事前にブラウザで確認し、プライバシーポリシーが表示されていることを確認できました。

4. Archive成功まで確認したこと

Simulatorで動いていても、Archiveで失敗することはあります。

申請直前で慌てないためにも、早めにArchiveを通しておくのは重要だと感じました。

次にやること

次のフェーズは、App Store Connect側の作業です。

具体的には以下です。

  • App Store Connectで新規Appを作成

  • Bundle IDを登録・紐付け

  • アプリ名、説明文、キーワードを入力

  • スクリーンショットを登録

  • プライバシーポリシーURLを登録

  • Support URLを登録

  • App Privacyを回答

  • 年齢制限を設定

  • ビルドをアップロード

  • 審査提出

特に注意したいのは、App Privacy と 年齢制限 です。

このアプリはビールを題材にしているため、実際に飲酒を促す内容ではないとしても、アルコール関連コンテンツとして年齢制限や表現には注意が必要です。

また、AdMobを利用しているため、App Privacyの回答でも広告・トラッキング・データ収集まわりを正しく入力する必要があります。

まとめ

個人開発アプリは、作るところも大変ですが、App Store申請前の整理もかなり大変です。

今回の作業を通して感じたのは、

「アプリが動く」ことと「申請できる状態になっている」ことは別物

ということです。

コードが完成していても、以下のような準備が必要になります。

  • アイコンが正しく揃っているか

  • 署名設定ができているか

  • Archiveが通るか

  • 実機で動くか

  • プライバシーポリシーが公開されているか

  • Support URLがあるか

  • 広告IDが正しいか

  • App Privacyに答えられる状態か

  • スクリーンショットが揃っているか

こうした作業を一つずつ潰していくことで、ようやくApp Store申請に進める状態になります。

今回はClaudeを使いながら、申請前の作業をかなり整理できました。

個人開発では、実装だけでなく、
申請・公開・運用まで含めて一つのプロダクトです。

ここからいよいよApp Store申請フェーズに進めていきます。
