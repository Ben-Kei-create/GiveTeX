ネストクラス

クラスの中にあるクラス。これまではクラス一個だとおもったが、クラスの中に、またちっこいクラスをつくれる。
大枠で囲ってる（エンクローズ）クラスをエンクロージングクラスといい、クラスの中にあるちっこいクラスをネストクラスという。

ネストクラスは全部で４種類ある。
・インナークラス
・staticクラス
・ローカルクラス
・匿名クラス

インナークラスって、そのままじゃん！と思ったが、アクセス修飾子はなんでもOK。

public class Outer {
    private String name;
    public void setName(String a){
        // do something
    }

    public class Inner {
        // XXX
    }
}

public void setName(String a)の部分は、void という（戻り値ないですよ〜という意味の戻り値の指定がある）値があり、setNameという名前、publicというアクセス修飾子（どっからでもOpenですの意味）がついているメソッドになる。戻り値、そしてString型の引数まで指定しているのですぐにメソッドとわかる。

そのメソッドの下には、同じくpublicがついているInnerの文字。これにclassがついてるので、これがインナークラスだとわかる。

アクセス修飾子は、private, protected, (デフォルト), publicのどれもOK。

しかし、mainメソッドのようにstaticをつけると、もう一個のネストクラスに様変わりする。これがstaticインナークラスと呼ぶ。わざわざ名前変えなくてよくね？と思うが、staticの制約が意外と多いので挙動がいろいろ代わる。なので分けているのだと思う。

staticインナークラスは、やはりクラスの中にあるクラスで、staticがくっついている。 staticなクラスにするだけでなく、staticなフィールドやstaticなメソッドにもくっつけることができる。

class Outer {
    static class StaticInner { // ← これが static インナークラス
        static int staticField = 100;
        int instanceField = 200;
        
        static void staticMethod() {
            System.out.println("Static method in StaticInner");
        }

        void instanceMethod() {
            System.out.println("Instance method in StaticInner");
        }
    }
}

これでOK。

上は、outerというエンクロージングクラスの中に、StaticInnerというstaticインナークラスがある。

そして、その中にはstaticなフィールドもstaticなメソッドもはいっている。

ちょっと疑問なのは、最初のインナークラスではその中にstaticとか入れられないのか？という疑問。結論、

通常の（非staticな）インナークラスの中には static フィールドや static メソッドを入れることはできない。

class Outer {
    class Inner {
        static int staticField = 100; // ❌ コンパイルエラー
        static void staticMethod() {  // ❌ コンパイルエラー
            System.out.println("Static method in Inner");
        }
    }
}

フツーのインナークラスでは、staticを入れるとコンパイルエラーがおきる。

本当めんどくさいのはここだけなので、もう少しお付き合い願いたいです。

class Outer {
    static class StaticInner { // ✅ static をつければOK！
        static void staticMethod() {
            System.out.println("Static method in StaticInner");
        }
    }
}

なので、このようにstaticなメソッドを作りたい場合はそのインナークラスをstaticクラスにしてもらえればOK

ここで超重要なのは、static制約を常に適用されること。

同クラス内で、
static→staticへのアクセスOK
static→非staticはアクセスNGです。

つまり、StaticInnerクラスから、外側のエンクロージングクラスの非staticメソッドや非staticなフィールドにアクセスすることはできない。

結論

外部クラス（エンクロージングクラス）は普通のクラスなので static メンバを持てる。
非staticなインナークラスは「外部クラスのインスタンスに依存」するから static メンバを持てない！
static メンバを持ちたいなら、インナークラスを static にする！

ネストクラスの中は、クラスの中にあるのはもちろんだが、クラスの直下でクラスをつくるのではなく、エンクロージングクラス内のメソッドの内部にあるネストクラスもある。つまり、メソッドの中に定義したネストクラスであり、これはローカルクラスと呼ぶ。

class Outer {
    void outerMethod() {
        class LocalClass { // ローカルクラス
            void show() {
                System.out.println("Hello from LocalClass");
            }
        }
        LocalClass lc = new LocalClass();
        lc.show();
    }
}

このローカルクラスのアクセス修飾子は？と思うが、これは不要になる。これが不要な理由としては、メソッドの中にあるから。
このローカルクラスは、outerMethod()内でしか使えない。よって、不要になる。
たとえば、以下のような形でもエラー

class Outer {
    void outerMethod() {
        private class LocalClass { // ❌ コンパイルエラー！
            void show() {
                System.out.println("Hello from LocalClass");
            }
        }
        LocalClass lc = new LocalClass();
        lc.show();
    }
}

使える範囲のことをスコープというが、
ローカルクラスはメソッドのスコープ内でしか使えないため、アクセス制御の概念が意味を持たない！となる。

結論

ローカルクラスには private は不要 & つけることができない！
そもそも Java には「ローカルメソッド」は存在しない！
（メソッドの中にメソッドは書けない）
ローカルクラスを使えばメソッドの中で処理をカプセル化できる！

演習

Q1. 次のコードについて正しい説明を選びなさい。

class Outer {
    static class StaticInner {
        void display() {
            System.out.println("Hello from StaticInner");
        }
    }
    
    void test() {
        StaticInner inner = new StaticInner();
        inner.display();
    }
}

public class Main {
    public static void main(String[] args) {
        Outer.StaticInner inner = new Outer.StaticInner();
        inner.display();
    }
}

①StaticInner のインスタンスは Outer クラスのインスタンスなしに生成できる。
②StaticInner のインスタンスは Outer クラスのインスタンスを作成しないと生成できない。
③StaticInner クラスは Outer クラスの test() メソッドからのみアクセス可能である。
④StaticInner クラス内のメソッド display() を static にしないとコンパイルエラーになる。

解説

StaticInner は static クラスなので、
Outer のインスタンスなしに new Outer.StaticInner() で直接インスタンス化できる。これは、static制約が優先されるためです。

Q2. 次のコードの実行結果として正しいものを選びなさい。

class Outer {
    private String message = "Hello from Outer";

    class Inner {
        void printMessage() {
            System.out.println(message);
        }
    }
    
    void test() {
        Inner inner = new Inner();
        inner.printMessage();
    }
}

public class Main {
    public static void main(String[] args) {
        Outer outer = new Outer();
        Outer.Inner inner = outer.new Inner();
        inner.printMessage();
    }
}

①Hello from Outer
②コンパイルエラーになる
③実行時エラー（NullPointerException）が発生する
④Hello from Inner

解説
Inner は非 static のインナークラスなので、Outer のインスタンスが必要。

outer.new Inner() で Outer のインスタンス outer を指定して Inner を作成することで message にアクセス可能。

class Outer {
    class Inner {  // 非staticインナークラス
        void show() {
            System.out.println("Hello from Inner");
        }
    }
}

public class Main {
    public static void main(String[] args) {
        Outer outer = new Outer();       // ① まず外部クラスのインスタンスを作る
        Outer.Inner inner = outer.new Inner();  // ② 外部クラスのインスタンス経由でインナークラスを生成
        inner.show();
    }
}

よって、正解は①

new Outer().new Inner();  //インナークラスの場合
new Outer.StaticInner();  //staticインナークラスの場合

Q3. 次のコードについて正しい説明を選びなさい。

class Outer {
    void outerMethod() {
        class LocalClass {
            static final String MESSAGE = "Hello";
            void print() {
                System.out.println(MESSAGE);
            }
        }
        LocalClass local = new LocalClass();
        local.print();
    }
}

①LocalClass はメソッドの外からインスタンス化できる。
②LocalClass に static フィールドを定義できないためコンパイルエラーになる
③LocalClass に static final フィールドを定義できるためコンパイル成功する
④LocalClass のメソッド print() は static でないとコンパイルエラーになる。

解説

これは②がひっかけ。staticはダメだが、コンパイラーにはならない。
なぜなら、static finalだから。

ローカルクラスは static メンバを持てないが、static final の定数 (final + コンパイル時に確定する値) は許可される！
LocalClass はメソッド内のローカルクラスなので、メソッドの外からはインスタンス化できない。
MESSAGE は static final の定数として定義できるのでコンパイル成功。
正解は③
